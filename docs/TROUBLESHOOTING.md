# 故障排查

按扩展加载、资源库登记、Agent 分发、运行时、原生认证、应用授权和界面操作逐层检查。保留错误原文，不用自动批准、关闭签名检查或关闭原始沙箱来掩盖问题。

## 扩展中找不到本插件

当前版本尚未发布，也未进入官方精选。请从 magpie“扩展”添加项目本地目录，而不是按已上架插件搜索。目录应包含完整项目入口及依赖，不要选择 `page`、`src` 或应用运行时目录。

GitHub 发布并不自动进入官方精选；维护者需要设置 `magpie-plugin` topic 参与发现，并另行向 magpie-community/plugins 提交收录。

## 扩展已添加，资源库没有 MCP 条目

1. 确认扩展已启用且加载完成，检查扩展加载错误。
2. 打开 Computer Use 设置页，确认路径和选项可以正常读取。
3. 重新加载扩展，再检查 **资源库 → MCP 服务器 → magpie-computer-use**。
4. 若出现同名冲突，先核对已有条目是否属于本插件，保留错误，不要覆盖无关配置。

设置页显示“已保存”只代表选项已写入。它不能证明扩展自动登记、MCP 连接或真实桌面操作成功。开发诊断见 [贡献指南](../CONTRIBUTING.md)，正常安装不要求用户手动注册 MCP。

## 资源库有条目，Agent 看不到工具

- 在条目中选择对应 Agent；自动登记不会替用户启用全部 Agent。
- 重新检测工具，然后重连目标 Agent 的 MCP，或新开会话。
- 确认目标 Agent 使用的是 magpie 分发的条目，没有同名旧配置。
- 仅看到 `js` / `js_reset` 时，检查是否连接了旧版或开发用脚本接口；本插件正常流程应提供十个操作工具。

Claude Code 可用 `/mcp` 查看连接状态。无交互界面的运行方式可能无法呈现授权询问；需要测试应用授权时使用能等待用户回答的交互式会话。

## 缺少运行时、签名失败或版本不兼容

插件需要 Apple Silicon macOS 和完整官方 `ChatGPT.app`。在设置页选择应用的实际绝对路径，默认是 `/Applications/ChatGPT.app`。

| 现象 | 检查与处理 |
| --- | --- |
| `此版本支持 Apple Silicon macOS` | 当前只支持 `darwin-arm64`，不支持 Intel 或其他系统 |
| `Select the complete original ChatGPT.app directory` | 选择完整原始应用目录，目录名为 `ChatGPT.app`，不是符号链接或内部 helper |
| `ENOENT`、缺少 `cua_node` 或组件 | 当前安装缺少完整运行时，确认官方版本包含 Node、`node_repl`、`cua-repl` 和 helper |
| `Application is not signed by OpenAI` / `codesign` 失败 | 应用/helper 身份或签名不符合要求，恢复完整官方安装后重新检测 |
| `Original CUA runtime manifest is incompatible` | 平台、架构或布局与当前实现不兼容，保留应用和运行时版本信息 |
| `Unexpected application identifier` | 显示名称相同但内部应用标识不符合当前要求，不能改名或重新签名解决 |

修改设置或更新应用后，重新加载扩展、重新检测资源库条目并重连 Agent。不要把不同版本的 helper 与运行时混用。

## `Sender process is not authenticated`

这是原始进程/连接认证路径的错误，与目标应用是否批准、macOS 是否已有权限不同。

1. 确认使用完整、原始签名有效的官方应用，相关组件来自同一套安装。
2. 在设置页核对应用路径。应用移动或升级后，关闭旧连接，重新加载扩展并检测条目。
3. 如果普通扩展环境可以发现应用，而某个 Agent 中失败，记录该 Agent 的启动环境、沙箱限制和错误尾部。
4. 需要进一步定位时，由维护者按贡献指南执行内部只读诊断，区分启动认证和客户端连接问题。

插件没有要求用户填写的认证 token，session/turn ID 也不是进程凭据。不要改代码跳过身份检查、重签官方应用、运行猜测的 helper 命令或自动 `accept` 授权。

## 原始 REPL 提示先选择应用

如果在同一连接、相同 `app` 且已调用 `get_app_state` 后，下一步仍提示 `Call get_app_state ... before interacting`，先确认扩展和 MCP 均已更新并重连。0.4.0 修复了旧包装在每个原始 REPL cell 重新声明共享 Map、清空目标的问题；新实现按 session/turn/app 绑定目标。不同上下文或不同 `app` 字符串仍必须重新选择。

## 能列出工具，但无法授权应用

工具发现只说明 MCP 连接和工具列表可用，不说明客户端支持 elicitation。

- 确认 Agent 能呈现 MCP elicitation，让用户明确选择。能力缺失、用户取消或连接断开时，该次授权会取消。
- 先执行 `list_apps`，再用明确应用标识调用 `get_app_state`，不要直接点击。
- magpie、Claude、Codex、终端或承载当前 Agent 的应用可能被宿主保护拒绝，这是预期边界；选用独立测试应用。
- 应用授权不替代 macOS 辅助功能或屏幕录制权限，按系统提示完成正常授权后重连。

不得控制 Agent 自己的窗口来批准授权，也不能把等待用户回答视为批准。

## 沙箱、进程启动与 helper 问题

外层 Agent 或开发工具的进程沙箱可能限制必需文件、IPC socket 或 helper 启动。先保留错误，再通过宿主支持的正常授权机制处理具体限制。外层启动限制与原始 node_repl 沙箱是不同层次。

插件不会关闭原始沙箱。继承环境中若存在 `LCU_ALLOW_AGENT_HOST_APPROVAL=1` 或关闭沙箱的配置，入口会拒绝启动，应移除这些旁路设置。

应用升级后仍报旧服务、socket 或版本错误时，正常关闭本插件 MCP 及相关旧会话，再重新启动；必要时由用户正常退出并重新打开官方应用。不要删除不明共享 socket/锁，或按名称批量杀死其他服务。内置恢复只有在核对服务归属并证明其失效后才执行。

## 保存设置后仍使用旧值

已运行的 MCP 不自动读取新设置。设置保存后由 magpie 重载插件，更新私有选项快照，再重连 Agent。若保存后没有应用新值，重新加载扩展并检查错误，然后重新检测资源库条目。改变本地插件目录后，也要在扩展中更新来源。

如果另有手工建立的旧条目，先核对归属，停止旧连接，避免两个同名定义混用。

## 界面操作或截图问题

- `Call get_app_state ... before interacting`：当前上下文没有选择该 `app`，或已被清理。重新选择，后续保持相同 `app` 字符串。
- 元素不存在或点击位置不对：重新读取界面，使用最新索引和截图。索引应是 `"12"` 这样的字符串。
- `click` 参数错误：元素索引与 `x`/`y` 二选一，不能混用。
- 辅助操作失败：只使用当前界面树明确给出的 action。
- 操作返回文字但没有新图：操作后通常返回新界面树，需要图片时再次调用 `get_app_state`。
- image block 已返回但未显示：检查 Agent 的图片渲染能力。
- 原始 API 返回不支持：保留错误，可能是目标控件或运行时限制，不能改写为成功。

## 滚动方向与内容预期相反

自有 AppKit 实测确认 `scroll` 会移动内容，但 `up` 使滚动条值从 0 增至约 0.844295，随后读到 1；`down` 使其回到约 0.127517，再回到 0。其方向表现与通常按文档内容位置理解的直觉相反。

这项限制的根因尚未查明，不要直接归因于系统“自然滚动”设置。先用小页数验证目标窗口的实际变化，重新读取界面后再继续；必要时使用界面树明确提供的滚动辅助操作。`isError: false` 只代表调用无工具错误，不足以证明方向符合预期。详见 [验证记录](VERIFICATION.md#已知限制滚动方向)。

## 超时、空闲断开或清理失败

请求活动预算默认 120 秒，等待用户授权时暂停；Agent 还可能设置自己的时限。空闲默认 5 分钟后清理并断开，后续重连后需重新选择应用。

取消或超时会清理当前上下文。出现 `Turn cleanup failed` 或原始 turn-ended handlers 超时，应正常关闭该 MCP 会话，等待清理后重连，不继续复用已结束上下文。

## Chrome 与浏览器能力

Chrome 开关只启用内部原始浏览器服务，不安装扩展/native host，不增加十工具之外的操作，也不自动授予网站权限。当前扩展主要面向 macOS 应用操作；浏览器脚本属于内部高级接口，实际验证边界见 [验证记录](VERIFICATION.md)。

## 停用后条目仍在

当前没有自动卸载钩子，扩展、资源库和已运行连接有各自状态。先在资源库取消该条目的 Agent 分发并移除条目，关闭连接，再在“扩展”停用或移除插件。若先删了扩展，应返回资源库清理遗留条目。系统和原始应用权限由用户单独管理，卸载不会自动撤销。
