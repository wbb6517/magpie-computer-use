# 故障排查

0.5.0 没有独立设置页。按扩展加载、资源库分发、本机 Codex 发现、原生连接和目标授权逐层检查；不要编辑旧选项 JSON 来修复新版问题。

## 没有设置页，资源库也没有条目

没有设置页是预期行为。确认已从 magpie“扩展”添加并启用插件，检查加载错误，重新加载后查看 **资源库 → MCP 服务器 → magpie-computer-use**。当前尚未发布或进入官方精选，本机使用本地项目目录。

同名冲突时先核对条目归属，不覆盖无关配置。旧本插件 `mcp --config` 仅在精确匹配兼容格式时保留；旧文件不再读取。新安装不要求手写 MCP 或运行注册命令。

## 找不到本机 Codex

安装或更新包含 Computer Use 组件的完整官方 Codex 桌面应用，再重连。发现支持继承的应用来源、运行中完整安装、两个 Applications 目录的标准应用名及 Spotlight；重命名应用可通过运行中路径或索引发现。

只有命令行 Codex、复制的 Node/helper、缺少 `cua_node` 的安装或符号链接不能代替完整桌面应用。发现后的身份和签名校验仍可能报错，应保留错误原文，不改签名或复制旧组件拼装。

多份完整应用同时运行时，若没有明确继承来源，保留所需的一份后重连。不要靠修改旧 `appPath` 选择版本；新版不读取它。

## Agent 看不到十个工具

在资源库选择该 Agent，重新检测并重连或新开会话。自动登记不自动分发给全部 Agent。仅出现 `js` / `js_reset` 时，检查旧条目或开发接口，正常扩展入口应提供十操作。Claude Code 可用 `/mcp` 查看服务。

## 已在 Codex 允许，为什么还问授权

先区分桌面 **Always-allowed apps** 的持久批准与另一会话中的临时允许。当前官方运行时复用前者，不承接任意其他会话的临时授权。确认在同一 macOS 账户中使用目标应用，再按原始询问作出选择。

原始运行时负责读取和保存批准；插件不维护第二份列表。不要编辑 `ComputerUseAppApprovals.json` 或把工具结果改成 `accept`。若当前 Agent 不支持 elicitation，新的询问会取消，应使用能显示询问并等待用户回答的会话。

应用批准不替代辅助功能或屏幕录制权限。按 macOS 和官方应用提示处理，不把登录、应用发现或已知 session ID 当作授权。

## `Sender process is not authenticated`

这是原始进程/连接认证错误，不是缺少可填写的登录 token。确认完整官方应用与 helper 来自同一套签名有效安装，更新后关闭旧 MCP 并重连，让插件重新发现。

保留原始错误，区分当前账户 helper、宿主继承管道与外层进程沙箱限制。插件沿用原始模块，不扫描其他会话 pipe；不要复制其他进程环境或借用其临时授权。开发诊断见 [贡献指南](../CONTRIBUTING.md)。

禁止通过关闭原始沙箱、跳过签名、读取账号凭据或自动批准目标来“修复”认证。若环境含宿主批准旁路或关闭沙箱的选项，移除这些设置后重试。

## 控制应用或截图失败

- 先调用 `get_app_state`，后续保持相同 `app`，使用最新索引；切换上下文或重连后重新读取。
- 同一上下文已选应用却仍提示先选择时，确认插件与 MCP 都已更新。旧版跨 cell 目标容器问题已采用独立绑定修复，但不能因此忽略真实上下文变化。
- 点击的索引和坐标二选一；操作后通常返回界面树，需要新截图时再调用 `get_app_state`。
- 只执行界面列出的辅助 action，不猜名称；原始 API 返回不支持时保留错误。
- 已返回 image block 但未显示时，检查 Agent 的图像呈现能力。
- magpie、Agent 宿主和授权界面仍受宿主保护，不用它们完成自我批准。

## 滚动方向相反

0.4.0 自有 AppKit 历史验收中，`up` 使滚动条值增大、`down` 使其减小，与内容位置直觉相反。根因未查明，不能认定由系统自然滚动设置引起，也没有新版普遍修复的结论。

先小幅滚动并重新读取目标界面，再继续；必要时使用界面明确提供的滚动辅助操作。`isError: false` 不能证明方向符合预期。详见 [历史验证](VERIFICATION.md#已知限制滚动方向)。

## 超时、空闲或浏览器问题

请求预算和空闲断开仅为本 MCP 内部连接管理，没有可调 UI，也不保证与 Codex 桌面每项时序相同。取消、超时或断开后正常重连并重新选择目标；出现清理失败时先关闭旧连接，不继续复用已结束上下文。

浏览器服务按原始组件存在情况启用，没有 Chrome 开关。组件存在不等于扩展/native host、网站授权和模型均已支持；不要从桌面十工具检测成功推断浏览器已验收。

## 停用与报告问题

先取消资源库分发并移除 MCP、关闭连接，再从“扩展”移除插件。当前无自动卸载钩子；Codex 持久批准与系统权限由原生界面管理，不随插件删除。

报告时提供插件、Codex 和 Agent 版本、系统架构、失败阶段及脱敏错误。不要提交原始批准文件、登录凭据、账号、私人应用列表、完整日志或个人截图。区分 0.5 新结果与 [0.4 历史记录](VERIFICATION.md)。
